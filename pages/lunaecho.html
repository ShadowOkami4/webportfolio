01 Three ways to run it

Same LunaEcho.
Different responsibility.

The product stays the same. What changes is who hosts it, which Discord bot identity it uses, and which operational limits apply.

01 / Your infrastructureFree, always

Open source

Self-Hosted

Run the complete LunaEcho platform on hardware you control, using your own Discord application and bot token.

Your hardware→Your bot→Your server
  • Complete open-source feature set
  • No artificial LunaEcho feature restrictions
  • Your data, branding, bot identity, and infrastructure
  • You handle setup, updates, backups, and uptime

Best forTechnical users who want full control

02 / Shared managed serviceFree

Invite and start

Cloud

Invite the official LunaEcho bot and use the platform without maintaining a VPS, Docker setup, database, or bot application.

LunaEcho hardware→LunaEcho bot→Your server
  • Hosting, maintenance, and updates included
  • Official shared LunaEcho bot identity
  • Useful core modules with reasonable service limits
  • No hardware or bot token required from you

Best forMost small communities

03 Platform foundation

One codebase.
Three runtime modes.

Self-Hosted, Cloud, and Custom are deployment choices, not separate bots. A fix in a module should improve LunaEcho for everyone.

SELF_HOSTEDCLOUD_SHAREDCLOUD_CUSTOM

Planned foundation

TypeScript throughout

Node.js, TypeScript, and discord.js connect the bot, API, dashboard, workers, and modules through shared types.

  • Next.js + React dashboard
  • PostgreSQL + Redis + BullMQ
  • Docker Compose for self-hosting
  • S3-compatible object storage
  • Prisma or Drizzle still to be evaluated

Custom token security

A bot token is a password.

Custom requires a real secrets system from day one. Customer bot tokens must be encrypted at rest and exposed only to the service that establishes the Discord connection.

  • Never included in logs, analytics, or support tickets
  • Never returned to the browser after submission
  • Excluded from normal database exports
  • Masked in the dashboard and replaced, never revealed

Two permission layers

Discord access is not billing access.

Discord permissions control what the bot can do. LunaEcho dashboard permissions control what staff can configure, inspect, or purchase.

  • Manage moderation or tickets
  • View logs and analytics
  • Edit automations and modules
  • Manage hosting, billing, and support access

Support boundaries

Responsibility follows hosting.

Self-Hosted receives documentation and community support. Cloud receives best-effort support. Custom adds managed support for LunaEcho infrastructure, deployment, updates, and billing.

  • No promise of 24/7 support at launch
  • No promise to repair third-party VPS setups
  • Third-party and Discord configuration remain separate
